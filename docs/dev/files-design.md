# `ak files` 설계

Mdir처럼 한 화면에서 디바이스와 PC의 폴더를 오가며 파일을 넣고(push) 꺼내고(pull) 지우는 대화형 파일 관리자입니다. **구현됨.** 이 문서는 상세 설계와 배경(실기기 확인 결과, 고른 이유) 기록입니다. 지켜야 할 규칙의 요약은 [cli-design.md §15](cli-design.md)에 있습니다.

## 1. 목표와 범위

- **목표:** `adb shell ls` · `adb pull` · `adb push`를 따로 치지 않고, 디바이스 폴더를 둘러보면서 키 몇 개로 파일을 주고받습니다.
- **기존 명령과의 관계:** `pull`은 그대로 둡니다. `files`는 터미널이 있어야만 동작하는 명령이라, 같은 일을 비대화형으로 하는 `pull` · `push`가 함께 있어야 원칙 6(사람이 없어도 동작)을 지킬 수 있습니다.
  - `ak pull`: 최근 파일을 골라 받기 (기존)
  - `ak push`: PC 파일을 디바이스에 올리기 (새로 추가, `files`보다 먼저 만듦)
  - `ak files`: 둘러보며 주고받고 정리하기
- **범위 밖:** 디바이스 루트 권한 작업, 앱 내부 저장소(`/data/data`), 원격 접속(망이 다른 경우). 셸 권한으로 접근할 수 있는 곳만 다룹니다.
- **업무 프로필 · 보조 사용자도 범위 밖입니다.** `/sdcard`는 주 사용자(0번) 저장소만 가리킵니다. 업무 프로필이 있는 Galaxy S24 Ultra(Android 16, 업무 프로필 = 사용자 10)에서 확인한 결과, 모든 경로가 막혔습니다.
  - `ls` · `adb pull` · `adb push`로 `/storage/emulated/10/...`에 접근 → `Permission denied` (`/data/media/10`, `/mnt/user/0/emulated/10` 등도 같음)
  - `content query` · `content read --user 10`, `pm list packages --user 10` → `SecurityException: Shell does not have permission to access user 10`
  - 원인: 업무 프로필에 기본으로 걸리는 `no_debugging_features` 제한(`dumpsys device_policy`의 `defaultEnabledRestrictionsAlreadySet`). adb 셸이 그 사용자에 접근하는 것 자체를 시스템이 거부하므로 우회할 수 없습니다.
  - 업무 프로필 파일은 기기 안에서 주 프로필로 공유한 뒤 다뤄야 합니다(회사 정책이 프로필 간 공유를 막을 수 있음).

- **이름:** 화면에서는 이 컴퓨터를 `Computer`라고 부릅니다(adb 도움말이 쓰는 말). `PC`는 Windows로 읽힐 수 있어서 쓰지 않습니다. 이 문서의 본문은 짧게 PC라고 씁니다.

## 2. 명령 정의

```
ak files [path]

  path  처음 열 디바이스 폴더 (기본: /sdcard)

  -s, --serial SERIAL   대상 디바이스 (공통)
```

- `Device: oneDevice`. 디바이스가 여러 대면 기존 선택 UI로 먼저 고릅니다.
- **터미널이 아니면** 바로 실패합니다.
  `Error: ak files needs a terminal` + `Hint: Use ak pull or ak push`
- `--json` 없음. 끝날 때 한 일을 stderr에 남깁니다(§8).
- 자동완성: `path`는 디바이스 경로라 제안하지 않습니다(`compArgs`에 "제안 없음").
- 에이전트용 SKILL.md에는 넣지 않습니다(대화형이라 에이전트가 쓸 수 없음). 대신 `pull` · `push`를 안내합니다.

## 3. 화면

### 한 창 (`9`로 PC 창을 닫았을 때): 두 단

```
 Galaxy S24 Ultra  /sdcard/DCIM/Camera
 ─────────────────────────────────────────┬────────────────────────────────────────────
   ..                                      │      20261117_090102.jpg  3.0M    2d
 [✓] 20261119_101533.jpg     3.2M     2m   │      20261117_090044.jpg  2.8M    2d
 [✓] 20261119_101540.mp4     430M     1m   │      20261116_181502.mp4  120M    3d
 ➤   20261118_220011.jpg     2.9M    12h   │      20261116_181455.jpg  3.1M    3d
 ───────────────────────────────────────────────────────────────────────────────────────
 Copy 3 files (12.0 MB) from Galaxy S24 Ultra:/sdcard/Download  6 Paste  Esc Clear
 4/48  0 folders  48 files  1.8 GB (54.0 GB free)  2 selected 433.2 MB

 1 Sort (s)      2 Recent (t)    3 Copy (c)      4 Cut (x)       5 To computer (g)
 6 Paste (v)     7 Mkdir (n)     8 Delete (d)    9 Show computer (w)   0 Rename (r)
```

- **머리글 아래 문자 키 줄:** 머리글과는 흐린 구분선으로 나눕니다(두 창이면 가운데에 `┴`). 번호가 없는 키를 보여 줍니다(`Tab Computer  ←→ Column  Space Select  a All  / Filter  : Go to  . Show hidden  b 1 column  ? Help  q Quit`). Enter(열기) · Backspace(상위)는 누구나 아는 키라 이 줄에서 빼고 도움말에 둡니다. `Esc`는 이 줄에 넣지 않고 쓰이는 자리에 보입니다: 복사 중이면 진행 줄의 `Esc Cancel`, 필터 중이면 상태 줄의 `filter: xx (Esc clears)`. 복사 · 질문 · 필터 때문에 이 줄의 줄 수가 바뀌어 목록이 움직이지 않게 하려는 것이고, 그래서 키가 한 줄에 들어가면 한 줄만 씁니다. 번호 키는 맨 아래, 문자 키는 머리글과 목록 사이라 화면 아래가 붐비지 않습니다. 한 줄에 다 들어가지 않으면 키 단위로 끊어 두 줄로 나눕니다. 높이가 모자라면 가장 먼저 줄입니다(두 번째 줄, 그다음 전부와 그 위 구분선).
- 맨 위 머리글: 위치(디바이스 이름 또는 `Computer`, 경로), 오른쪽에 필터와 정렬 기준(`name ↑` · `newest ↓` · `size ↓`). 정렬은 창마다 따로이고(`1`은 커서가 있는 창만 바꿈), 최근 파일 보기는 폴더와 따로 정렬하며 최신순으로 시작합니다. 그래서 두 창 모두 머리글에 자기 정렬을 보입니다.
- **두 단(mc brief 방식):** 한 창이고 폭이 80칸 이상이면 목록을 신문처럼 두 단으로 놓습니다. 왼쪽 단이 앞부분, 오른쪽 단이 이어지는 부분이고 사이에 `│`가 있습니다. 스크롤은 한 단씩 밉니다: 처음 1~10 | 11~20, 커서가 21로 가면 11~20 | 21~30. `..`은 첫 항목입니다. 80칸 미만이면 한 단입니다. 최근 파일 보기도 같습니다(폴더 접미사는 자리가 있을 때만).
- 목록: 이름, 크기, 수정 시각. 시각은 일주일 안이면 상대 시간(`now`, `5m ago`, `12h ago`, `3d ago`), 그보다 오래면 날짜입니다: 올해는 `11-03 14:05`, 그 전 해는 `2025-11-03`. 두 단 · 두 창에서는 폭이 좁아 `5m`, `11-03`, `2025`로 줄이고, 두 단에서는 크기도 `3.2M` · `430M` · `12K`로 줄입니다. 기기 시계가 PC보다 앞서 미래 시각이면 날짜로 보입니다. 폴더는 이름 뒤에 `/`, 크기 칸은 비웁니다. **긴 이름:** 다른 줄은 가운데를 줄여(`ONEBillingLab-releas…0251222-1349.apk`) 앞이 같은 이름도 끝(버전 · 날짜 · 확장자)으로 구별됩니다. 커서 줄은 크기 · 날짜 칸까지 덮어 전체 이름을 보이고, 그 크기와 날짜는 상태 줄의 위치 뒤에 시안으로 옮겨 보입니다. 그래도 줄보다 길면 1초 뒤 한 칸씩(0.15초) 왼쪽으로 흘려 끝까지 보이고 1.5초 멈춘 뒤 처음부터 다시 합니다. `b`(brief)는 한 창에서 두 단 ↔ 넓은 한 단을 바꿔, 긴 이름을 많이 볼 때 씁니다(커서는 같은 항목에 남음). 이름 색은 확장자가 아니라 이 사용자(기기에서는 adb 셸)가 그 항목으로 할 수 있는 일을 보입니다. 앞의 것이 우선입니다: 읽을 수 없음(폴더는 목록을 볼 수 없음) 빨강, 심볼릭 링크 보라, 읽기 전용(꺼내기는 되지만 그곳에 넣기 · 이름 바꾸기 · 삭제는 안 됨) 노랑, 폴더 파랑, 실행 파일 초록, 숨김 파일 흐리게. 커서 위 항목은 상관없이 시안입니다. 기기는 목록을 읽는 같은 adb 호출에서 셸의 `[ -r ] [ -w ] [ -x ] [ -L ]`로 확인합니다(셸 내장이라 파일마다 프로세스를 띄우지 않음, 권한 비트가 아니라 파일 시스템에 묻기 때문에 FUSE인 `/sdcard`에서도 맞음). 컴퓨터는 `access(2)`와 `lstat`(Windows는 읽기 전용 속성만)으로 확인합니다. 폴더가 먼저 오고 그다음 파일입니다.
- **상태 줄(항상 1줄):** 커서 위치/전체(`..`은 빼고 셈), 현재 폴더 바로 아래의 폴더 수 · 파일 수 · 파일 크기 합(숨김은 보일 때만, 재귀 아님), 디바이스 쪽이면 크기 합 바로 뒤에 흐린 괄호로 남은 공간(`1.8 GB (54.0 GB free)`; `df -k`를 폴더를 열 때와 넣기 · 꺼내기 · 삭제 뒤에 읽고, 실패하면 생략. PC 쪽은 생략), 선택이 있으면 `N selected 크기`, 필터 중이면 `filter: xxx`. 최근 보기에서는 `Recent 2/300 (54.0 GB free)`. 두 창에서는 커서가 있는 창 기준입니다. 메시지(결과 · 경고), 진행 줄, 입력 줄(필터 · 이름), 질문(같은 이름 · 삭제)은 이 줄 자리를 잠시 대신 씁니다. 메시지는 다음 키에 사라집니다.
- **클립보드 줄:** 상태 줄 바로 위에 늘 한 줄을 잡아 둡니다. 담은 것이 있으면 `Copy 3 files (12.0 MB) from Galaxy S24 Ultra:/sdcard/DCIM  6 Paste  Esc Clear`(잘라내기면 `Cut …`), 없으면 빈 줄입니다. 담고 비울 때 목록이 움직이지 않게 하려는 것입니다.
- 상태 줄과 번호 키 바 사이는 빈 줄 하나로 띄웁니다. 높이가 모자라면 이 빈 줄, 그다음 클립보드 줄을 가장 먼저 뺍니다.
- **번호 키 바:** 지금 쓸 수 없는 키(진행 중의 3 · 4 · 5 · 6 · 7 · 8 · 0, 최근 보기의 6 · 7, 클립보드가 빌 때 6, `..` 위의 0, 좁은 창의 9 등)도 라벨을 남기고 숫자 · 라벨을 흐리게, 별칭 없이 그립니다. 색이 꺼지면 라벨 앞에 `×`를 붙여(`6 ×Paste`) 색 없이도 "지금 안 됨"이 읽힙니다. 눌러도 아무 일이 없습니다.
- **번호 키 바:** mc의 F키 바처럼 칸을 나눠 숫자(굵게 시안), 한 칸 띄고 라벨, 그 뒤에 같은 일을 하는 문자 키(번호 키 바 전에 쓰던 키)를 흐리게 괄호로 둡니다: `9 Show computer (w)`. `3 Open`은 Enter라 문자 키를 붙이지 않고, 칸에 자리가 없으면 문자 키부터 뺍니다. 폭이 160칸 이상이면 한 줄에 10칸, 그보다 좁으면 라벨이 잘리지 않게 두 줄(1~5 위, 6~0 아래)로 나눕니다. 그래도 칸이 좁으면 라벨을 칸에 맞춰 자릅니다. 지금 쓸 수 없는 키는 라벨이 빕니다. 문자 키(Tab · Space · `/` 등)는 머리글 아래 문자 키 줄에 있습니다. 질문 · 입력 중에는 이 자리에 그 모드의 키 안내를 보입니다(`y Delete  n Esc q Keep` 등).
- 높이가 모자라면 문자 키 줄(두 번째 줄, 그다음 전부) → 번호 키 바의 두 번째 줄(한 줄로 줄임) → 번호 키 바 → 구분선 → 머리글 순으로 뺍니다. 상태 줄은 남깁니다.
- 처음 화면은 두 창(왼쪽 디바이스, 커서는 디바이스 쪽)입니다. 80칸 미만이면 디바이스 한 창으로 시작합니다.

### 두 창 (처음 화면, `9`로 켜고 끔)

- PC 창은 기본으로 켜져 있습니다. 창이 80칸 미만으로 좁아지면 한 창이 되고, 다시 넓어지면 PC 창이 돌아옵니다. `9`로 끄면 넓어져도 다시 `9`를 누를 때까지 꺼진 채입니다.

```
 Galaxy S24 Ultra  /sdcard/DCIM/Camera   │ Computer  ~/Downloads
 ────────────────────────────────────────▶────────────────────────────────
   ..                                    │   ..
 [✓] 20261119_101533.jpg  3.2 MB   2m    │ ➤ app-release.apk   12 MB  3d
 ➤   20261119_101540.mp4  430 MB   1m    │   notes.txt          2 KB  1h
```

- 왼쪽이 디바이스, 오른쪽이 PC입니다(고정). 각 창은 한 단(위아래 스크롤)입니다. 커서가 있는 창만 `➤`와 강조를 보이고, 위 · 아래 구분선의 그 창 쪽 절반을 시안색으로 칠합니다(다른 창은 흐리게). 어느 쪽에서 작업 중인지 바로 보이게 하려는 것입니다. 두 단 ↔ 두 창을 바꿔도 커서 항목은 그대로이고, 보이도록 스크롤만 다시 맞춥니다.
- 머리글 아래 가운데 교차점은 `5`로 데이터가 갈 방향입니다: 커서가 디바이스 쪽이면 `▶`, PC 쪽이면 `◀`. 색이 꺼져도 기호는 그대로입니다.
- **터미널 폭이 80칸 미만이면**(두 단 보기와 같은 기준) 두 창을 켜지 않고 `9`의 라벨도 비우며, 상태 줄에 `Window too narrow for two panes`를 잠깐 보입니다. 두 창 상태에서 폭이 줄면 커서가 있던 쪽 한 창으로 돌아갑니다. 파일 이름이 잘려 못 읽는 것보다 낫기 때문입니다.
- 기존 선택 UI 규칙을 그대로 따릅니다: 대체 화면, stderr에 그리기, 터미널보다 높게 그리지 않기, `ui.Fit`, 크기 바뀌면 다시 그리기, 색이 꺼지면 기호만으로 구분([cli-design.md §10](cli-design.md)).

## 4. 키

mc의 F키 배치를 숫자로 씁니다. macOS 터미널에서는 F키가 밝기 · 볼륨 같은 시스템 기능에 먼저 걸리기 때문입니다. 기존 선택 UI는 글자를 치면 바로 필터가 되지만, `files`에서는 글자 · 숫자가 동작 키라서 필터는 `/`로 시작합니다. 필터 · 이름 입력 중에는 숫자도 글자로 들어갑니다.

| 번호 키 | 동작 | 별칭 |
|---|---|---|
| `1` Sort | 커서가 있는 창의 정렬 바꾸기: 이름 → 최신순 → 크기 (최근 파일 보기는 따로) | `s` |
| `2` Recent | 디바이스의 최근 파일 보기 ↔ 폴더 보기 (§7). PC 쪽에서 누르면 커서를 디바이스 쪽으로 옮기고 최근 파일을 엽니다 | `t` |
| `3` Copy | 대상을 클립보드에 복사로 담기 (§6) | `c` |
| `4` Cut | 대상을 클립보드에 잘라내기로 담기(붙여넣으면 이동) | `x` |
| `5` To computer / To device | 바로 반대쪽 창의 현재 폴더로 복사: 디바이스 쪽이면 꺼내기(pull), PC 쪽이면 넣기(push) | `g` · `p` |
| `6` Paste | 클립보드를 커서가 있는 창의 현재 폴더에 붙여넣기 | `v` |
| `7` Mkdir | 새 폴더 | `n` |
| `8` Delete | 삭제 (확인) | `d` · Delete |
| `9` Show computer / Hide computer | PC 창(두 창) 켜기/끄기 | `w` |
| `0` Rename | 이름 바꾸기 (최근 보기에서도) | `r` |

도움말은 `?`, 끝내기는 `q` · Ctrl+C입니다(바에 넣지 않음). 열기는 Enter입니다(예전 `3 Open`은 없앰).

| 문자 키 | 동작 |
|---|---|
| ↑ ↓ | 한 칸 (두 단에서는 단 끝에서 옆 단으로 이어짐) |
| ← → | 두 단: 옆 단의 같은 줄(없으면 그 단의 마지막 항목, 첫 단에서 ←는 단 단위 스크롤 또는 무시). 한 단(두 창 · 80칸 미만): ← 상위 폴더, → 들어가기 |
| PgUp PgDn · Home End | 한 화면(두 단이면 두 단)씩 · 처음과 끝 |
| Enter | 열기 (§5) |
| Backspace | 상위 폴더 |
| Space | 선택/해제 후 한 칸 아래로 |
| `a` | 이 폴더 전체 선택/해제 (install · pull · push 선택 화면과 같은 키) |
| `/` | 이름 필터 (Esc로 끄기) |
| `:` | 경로를 입력해 이동 |
| `.` | 숨김 파일 보이기/숨기기 (기본 숨김) |
| `b` | 한 창: 두 단 ↔ 넓은 한 단 |
| Tab | 한 창: 디바이스 ↔ PC 전환 / 두 창: 커서를 반대쪽 창으로 |
| Esc | 진행 중인 복사 · 삭제 취소 > 필터 끄기 > 클립보드 비우기 (이 순서로 하나) |
| `?` · `q` | 도움말 · 끝내기 |

- 각 쪽(디바이스 · PC)은 보던 폴더, 커서, 선택을 따로 기억합니다. 모드를 바꾸거나 Tab을 눌러도 그대로입니다.
- `3` · `4` · `5` · `8`의 대상: 지금 보이는 행 가운데 선택한 항목이 있으면 그것, 없으면 커서 위 항목. 필터나 숨김에 가려진 선택은 무시합니다(해제하지는 않음).
- `5`의 라벨은 처음 보는 사람도 알 수 있게 말로 씁니다: 디바이스 쪽이면 `To computer`, PC 쪽이면 `To device`. 진행 줄 · 요약 · 두 창 구분선은 기기를 왼쪽에 둔 화살표(`→` · `←`, `▶` · `◀`)로 방향을 보입니다.

### 도움말 (`?`)

목록 위 영역 전체(머리글부터 목록 끝까지)를 덮는 화면입니다. 묶음은 Move · Select · Copy · How things work · Manage · View · Colors · Status line 순서이고, 각 키 옆에 같은 일을 하는 문자 별칭을 흐린 괄호로 적습니다(`8 Delete (d)`). 별칭만 모아 둔 줄은 따로 두지 않습니다. How things work에는 열기(기기 파일은 임시 폴더로 복사한 뒤 엶, 실제 경로 표시), 삭제(기기 `rm -rf`, 컴퓨터도 영구 삭제), 최근 파일, 남은 공간, 기기 권한(주 사용자 저장소만)을 설명합니다. 120칸 이상이면 묶음을 두 칸으로 나눠 배치하고(두 칸 중 긴 쪽이 가장 짧아지는 곳에서 묶음 단위로 나눔), 좁으면 한 칸입니다. 키 이름은 자르지 않고 설명만 줄바꿈하며, 설명 칸이 24칸 미만이면 설명을 키 아래 줄로 내립니다. 화면보다 길면 맨 아래에 `↑↓ PgUp PgDn scroll · any other key closes`를 보이고 ↑↓ · PgUp PgDn · Home End로 넘깁니다. 그 밖의 키는 닫기입니다.

## 5. Enter (열기)

| 커서 위치 | 동작 |
|---|---|
| 폴더 · `..` | 들어가기 / 상위 폴더 |
| 디바이스의 파일 | PC 임시 폴더로 받아 기본 앱으로 열기 (`screenshot -o`와 같은 열기) |
| PC의 `.apk` | 지금 디바이스에 설치 (`install`의 자동 복구 그대로, 확인 질문은 화면 안에서) |
| PC의 그 밖의 파일 | 기본 앱으로 열기 |

- 디바이스 파일을 폰 화면에서 여는 방식(`am start` VIEW)은 쓰지 않습니다. Android 7부터 `file://` 공유가 막혀 앱마다 결과가 다르기 때문입니다.
- **열기는 커서 위 파일 하나만** 합니다. 선택은 쓰지 않습니다(100개를 선택해 두고 열어도 창 100개가 뜨지 않게). 선택이 있는 채로 열면 결과 메시지에 `(open takes the file under the cursor; the selection is for 3, 4, 5 and 8)`를 붙여 선택이 무엇에 쓰이는지 알립니다.
- 임시 파일은 사용자별 캐시 폴더(`os.UserCacheDir()/ak/files/`, 예: macOS `~/Library/Caches/ak/files`, Linux `~/.cache/ak/files`)에 두고, 실패하면 `os.TempDir()/ak-files/`에 둡니다. Linux의 `/tmp`는 사용자끼리 같이 써서 권한이 부딪히기 때문입니다.
- 끝날 때 바로 지우지 않습니다(아직 읽고 있는 앱이 실패할 수 있음). 다음 실행 때 하루가 넘은 하위 폴더만 지웁니다. 동시에 실행 중인 다른 `ak files`가 막 연 파일은 남습니다.

## 6. 복사: 넣기 · 꺼내기(5)와 클립보드(3 · 4 · 6)

- **5는 바로 반대쪽으로 복사합니다**(원본은 그대로). 아래 넣기 · 꺼내기 규칙입니다.
- **클립보드(3 Copy · 4 Cut · 6 Paste):** 처음엔 클립보드를 없애고 5만 두었지만, 여러 폴더의 파일을 한곳에 모으려면 폴더를 옮길 때 선택이 사라져 할 수 없었습니다. 그래서 ak 안의 클립보드(OS 클립보드 아님)를 다시 두었습니다.
  - 3/4는 대상을 담고 그 폴더의 선택을 비웁니다. 클립보드는 폴더 · 창을 옮겨도 유지되고, 다시 담으면 바뀝니다. Esc는 진행 중 작업 취소 > 필터 끄기 > 클립보드 비우기 순으로 하나만 합니다.
  - 6은 커서가 있는 창의 현재 폴더에 붙여넣습니다(최근 보기에서는 막고 안내). 경로: 디바이스 → PC `adb pull`, PC → 디바이스 `adb push`(최상위 이름 NFC), 같은 디바이스 `cp -r`, PC 안 파일 복사.
  - Cut은 이동입니다. 같은 쪽은 rename(`mv`, 대상이 있으면 거부하는 Rename 규칙. PC에서 다른 볼륨이면 복사 → 확인 → 삭제), 다른 쪽은 복사 뒤 크기 · 파일 수가 맞을 때만 원본을 지웁니다. 크기를 모르면 원본을 남기고 실패로 둡니다. 옮겨서 지운 기기 폴더는 MediaStore 행도 정리합니다.
  - Copy 붙여넣기는 클립보드를 남겨 여러 곳에 붙일 수 있고, Cut 붙여넣기는 성공한 항목만 클립보드에서 빠집니다(전부 성공하면 비움).
  - 같은 폴더에 Copy면 ` (N)` 사본, Cut이면 아무것도 하지 않습니다. 폴더를 자기 안으로 붙여넣으면 거절합니다(PC는 `EvalSymlinks`로 실체 비교, 기기는 한 번의 셸 호출로 `pwd -P` 비교, 링크 · `/sdcard` 별칭 포함). 원본이 덮어쓸 대상 안에 있으면(`/x/A/A`를 `/x`의 `A` 위에) 덮어쓰기를 거절합니다.
  - 같은 이름 질문 · 덮어쓰기(임시 이름 → 확인 → 교체) · 진행 막대 · Esc 취소 · 요약(`Copied …` · `Moved …`와 항목 목록) · 남은 공간 갱신은 5와 같습니다. 붙여넣은 폴더와(이동이면) 출발 폴더를 다시 읽습니다.
- **`5` 넣기(PC 쪽, 별칭 `p`):** 대상을 디바이스 쪽 현재 폴더로 `adb push`.
- **`5` 꺼내기(디바이스 쪽, 별칭 `g`, 최근 파일 보기 포함):** 대상을 PC 쪽 현재 폴더로 `adb pull`.
- 한 창이어도 같습니다. 반대쪽이 화면에 없어도 그쪽이 기억하는 현재 폴더가 도착지입니다.
- 확인 질문 없이 바로 시작합니다. 같은 이름이 있을 때만 묻습니다.
- **덮어쓰기는 기존 것을 먼저 지우지 않습니다.** 같은 폴더에 `.ak-tmp-<이름>`으로 복사하고 크기 · 파일 수를 확인한 뒤, 기존 것을 `.ak-old-<이름>`으로 옮기고 새 것을 제자리로 옮긴 다음 `.ak-old-`를 지웁니다. 실패하거나 취소하면 이번에 만든 것만 지우고 기존 것은 되돌립니다.
- **이름 비교는 대소문자를 무시합니다.** macOS(APFS) · Windows · Android `/sdcard`가 모두 대소문자를 구분하지 않아서, 구분하면 `Photo.JPG`가 `photo.jpg`를 묻지 않고 덮어씁니다. 대소문자만 바꾸는 이름 바꾸기는 허용합니다.
- 최근 파일 보기에서 여러 폴더의 같은 이름을 함께 꺼내면 뒤의 것에 ` (N)`을 붙입니다.
- adb push는 빈 폴더를 건너뛰므로, 폴더를 넣은 뒤 빈 폴더를 `mkdir -p`로 만듭니다.
- **이름의 정규화(NFC · NFD):** macOS Finder가 만든 한글 이름은 자모가 분리된 NFD로 저장됩니다. Pixel(Android 16)은 NFD로 넣은 이름을 NFC로 바꿔 저장했지만 Galaxy S24 Ultra(Android 15)는 NFD 그대로 저장해, 기기의 앱들이 자모를 벌려 보였습니다. 그래서 넣을 때(`push` · `ak files` 5) 최상위 이름은 NFC로 바꿔 저장합니다. 꺼낼 때는 이름을 그대로 둡니다. 이름 비교(충돌 · 같은 이름)는 NFC + 소문자로 하므로 NFD로 이미 있는 이름과도 겹침으로 잡히고, 덮어쓰기는 기존 항목의 실제 경로로 바꿔 넣습니다. 화면에는 이름을 NFC로 보이고, 폭 계산은 분리된 중성 · 종성 자모를 0칸으로 셉니다(`ui` 전체). 경로 자체(Stat · rename · adb 인자)는 원래 바이트를 씁니다(macOS는 NFD 경로로만 열림).
  - **한계:** 폴더를 넣을 때 안쪽 이름은 adb push가 그대로 올리므로 NFD가 남을 수 있습니다. 바꾸려면 넣은 뒤 기기에서 항목마다 `mv`가 필요해 비용이 큽니다. 더 나은 방법은 폴더를 넣기 전에 컴퓨터 쪽 임시 폴더로 NFC 이름 사본을 만드는 것이지만 큰 폴더는 디스크 · 시간이 두 배라 이번에는 하지 않았습니다.

### 같은 이름이 있을 때

상태 줄에 묻습니다.

```
 'IMG_0001.jpg' already exists.  o Overwrite  s Skip  r Rename (N)  · Shift = all
```

- 소문자는 이 파일만, 대문자(`O` `S` `R`)는 남은 파일 전부에 적용합니다.
- 기본값(Enter)은 Rename입니다. 데이터를 잃지 않는 쪽입니다. Esc · `q`는 이번 넣기 · 꺼내기를 취소합니다(`q`를 한 번 더 누르면 끝냄).

### 진행 표시

```
 Pushing 2/3  video.mp4  Galaxy S24 Ultra:/sdcard/Download ← Computer  ████████░░░░░░░░░░░░ 42% (180 / 430 MB)  Esc Cancel
 Pulling 2/3  video.mp4  Galaxy S24 Ultra → ~/Downloads  ████████░░░░░░░░░░░░ 42% (180 / 430 MB)  Esc Cancel
```

- 기기를 항상 왼쪽에 두고 화살표는 화면 방향입니다. PC 경로는 `~`로 줄입니다.
- 막대는 줄의 남은 폭을 채우되 10~40칸입니다. 채운 부분 `█`, 빈 부분 `░`(색이 꺼져도 기호로 보임). 여러 개면 막대 · 퍼센트 · 크기는 지금 항목(파일 또는 폴더)의 바이트 기준이고, 몇 번째인지는 `2/3`으로 봅니다.
- 폭이 모자라면 파일 이름 · 경로를 먼저 줄이고, 그다음 크기 숫자 `(… / … MB)`를 빼고, 막대는 10칸까지 줄입니다. 퍼센트는 항상 남깁니다.
- 바이트 진행률은 전체 크기를 알 때(디바이스 `stat` · PC `os.Stat`) 받는 쪽 파일 크기를 주기적으로 확인해 계산합니다. 모르면 막대 없이 스피너만 돕니다.
- 넣기 · 꺼내기 동안에도 화면은 움직일 수 있지만, 동작 키(`5` `6` `7` `8`과 별칭)는 막습니다.
- **Esc · Ctrl+C:** 지금 파일을 멈추고, 덜 받은 파일은 지우고, 남은 파일은 하지 않습니다.
- 끝나면 상태 줄에 `✓ Pulled 3 files from Galaxy S24 Ultra → ~/Downloads` 또는 `2 of 3 pulled, 1 failed`를 보입니다. 실패가 있으면 Enter로 실패 목록(파일, adb 원본 메시지)을 엽니다.

### 미디어 스캔

- Android 11(API 30)부터는 `/sdcard` 쓰기가 FUSE를 거치므로 push · `mv` · `rm` 결과가 MediaStore에 바로 반영됩니다(Pixel 9 Pro Android 16, Galaxy S24 Ultra Android 15에서 확인). 따로 스캔하지 않습니다.
- 단, 폴더를 지우면 폴더 항목(`format=12289`)은 MediaStore에 남습니다(Pixel 9 Pro Android 16에서 확인). 최근 파일 쿼리가 폴더를 빼므로 `pull` · 최근 파일 보기에는 영향이 없습니다.
- Android 10 이하에서는 바뀐 파일마다 `am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file://<path>`를 보냅니다. **10 이하 실기기에서 확인 필요.**

## 7. 최근 파일 보기 (`4`)

- MediaStore가 아직 스캔하지 않은 새 파일은 크기와 수정 시각이 한동안 NULL입니다(Pixel 9 Pro · Galaxy S24에서 25초 넘게 확인). 빼지 않고, 정렬은 `COALESCE(date_modified, date_added)`로 해서 맨 위에 옵니다. 그런 항목만 모아 기기에서 `stat` 한 번(100개씩)으로 실제 크기와 수정 시각을 채웁니다(`FillUnknownSizes`, `ak pull`도 같음). stat도 못 읽으면 크기 `?`, 상태 줄에서는 뺍니다.
- 디바이스 쪽 목록을 `pull`과 같은 MediaStore 최신순 목록으로 바꿉니다(최대 300개). 각 줄에 폴더 경로를 흐리게 붙입니다.
- 여기서도 `3` · `4` · `5`(꺼내기) · `8` · `0`(이름 바꾸기) · Enter가 그대로 동작합니다. 꺼내기는 PC 쪽 현재 폴더로 갑니다. 이름 바꾸기는 그 항목의 폴더를 그 자리에서 읽어 같은 이름 규칙으로 확인하고, 목록의 이름만 고칩니다(MediaStore를 다시 조회하지 않음). 그 폴더를 보는 폴더 보기는 다시 읽습니다. `6` · `7`은 쓸 수 없습니다.
- 처음 열 때 `content query`가 약 1초 걸립니다(데이터 양과 무관한 고정 비용). 그동안 목록 자리에 스피너를 보입니다.

## 8. 삭제·이름 바꾸기·새 폴더

- **삭제는 항상 확인합니다.** 상태 줄에 묻습니다.
  - 디바이스: `Delete 3 items from Galaxy S24 Ultra? This cannot be undone. [y/N]` → `rm -r`
  - PC: 1단계는 디바이스와 같이 `[y/N]` + `This cannot be undone.` 확인 후 영구 삭제(`local.go`의 `deleteLocal` 한 곳). 휴지통은 §10에서 정함
- 이름 바꾸기 · 새 폴더는 아래 줄에서 입력받습니다. 빈 이름, `/` 포함, 이미 있는 이름은 거절합니다.
- 디바이스 명령에 넘기는 경로는 모두 셸 따옴표 처리를 합니다(공백 · 한글 · `'` 포함 이름).

### 끝날 때 남기는 기록

대체 화면이 닫히면 셸 화면에는 아무것도 남지 않으므로, 한 일을 stderr에 요약합니다.

```
✓ Pulled 3 files from Galaxy S24 Ultra → ~/Downloads
✓ Pushed 'a.txt' as 'a (1).txt' to Galaxy S24 Ultra:/sdcard/Documents ← Computer
✓ Renamed 'b.txt' to 'c.txt' on Galaxy S24 Ultra
✓ Made folder 'x' in ~/Downloads
✓ Deleted 2 items on Galaxy S24 Ultra
Warning: Canceled pushing to Galaxy S24 Ultra:/sdcard/Download ← Computer: 1 of 3 pushed
```

여러 항목을 다룬 줄 아래에는 그 이름들을 흐리게 들여 써서 보입니다(폴더는 `/`, 이름이 바뀐 것은 `a.txt → a (1).txt`, 20개까지 보이고 나머지는 `… and N more`).

실패가 있었으면 종료 코드 1, 없으면 0, Ctrl+C로 끝냈으면 130입니다([cli-design.md §4](cli-design.md)).

## 9. 구현 구조

- **목록 읽기:** 디바이스는 `stat -c '%F|%s|%Y|%n' <dir>/* <dir>/.*`(폴더 하나에 0.1초 안팎). `%n`이 마지막이라 앞의 세 `|`까지만 자르면 이름에 `|`가 있어도 안전합니다. 이름에 줄바꿈이 있는 파일은 건너뜁니다. 파싱은 순수 함수(`parseStat`)로 분리해 테스트합니다.
- **두 저장소를 같은 인터페이스로:** `List`, `Stat`, `Mkdir`, `Rename`, `Remove`, `Usage`를 가진 인터페이스에 `deviceFS`(adb) · `localFS`(os) 두 구현. 넣기는 `adb push`, 꺼내기는 `adb pull`입니다.
- **화면:** 새 패키지 `internal/files`(가칭)에 상태(`state.go`, 순수 로직)와 그리기(`render.go`)를 나눕니다. 키 해석 · raw 모드 · 크기 변경 감지는 `internal/tui`의 것을 공개해서 같이 씁니다. 지금 `tui.Select`는 고르고 끝나는 picker라 그대로 늘리지 않습니다.
- **테스트:** 상태 전이(이동 · 선택 · 넣기 · 꺼내기 · 충돌 처리)는 순수 함수 테스트, 복사 흐름은 `adbtest.Fake` + 임시 폴더로 테스트합니다.

## 10. 순서와 정할 것

### 만드는 순서

1. `pull` 조회 스피너 (작은 개선, 먼저)
2. `ak push` (비대화형 짝)
3. `ak files` 1단계: 한 창 · 두 창, 탐색, Enter 열기, 넣기 · 꺼내기, 충돌 처리, 진행률, 삭제 · 이름 바꾸기 · 새 폴더, 최근 파일 보기
4. `ak files` 2단계: 정렬, 숨김 파일, 경로 이동(`:`), `.apk` 설치
5. `ak files` 3단계(필요하면): 디바이스 바꾸기, 디바이스 A → B 복사(PC 임시 폴더 경유), 앱 목록에서 APK 추출

### 정할 것

- **PC 삭제 방식:** macOS는 Finder(`osascript`)로 지우면 "되돌리기"가 되지만 처음 한 번 자동화 권한을 묻습니다. `~/.Trash`로 옮기면 권한은 필요 없지만 되돌리기가 안 됩니다. Linux는 freedesktop 휴지통 규격, Windows는 셸 API가 필요합니다. 휴지통을 못 쓰는 환경에서는 영구 삭제 + 강한 확인으로 할지 정해야 합니다.
- **`Android/data` · `Android/obb`:** 버전 · 제조사에 따라 셸 권한으로도 막힙니다. 막히면 목록 자리에 `Permission denied`를 보이는 것으로 충분한지.
- **`push`의 기본 위치:** `/sdcard/Download`로 할지.
