# `ak files` 설계

Mdir처럼 한 화면에서 디바이스와 PC의 폴더를 오가며 파일을 복사·이동·삭제하는 대화형 파일 관리자입니다. 아직 구현 전 설계 문서이며, 구현하면서 정해진 규칙은 [cli-design.md](cli-design.md)에 새 절로 옮기고 이 문서는 지웁니다.

## 1. 목표와 범위

- **목표:** `adb shell ls` · `adb pull` · `adb push`를 따로 치지 않고, 디바이스 폴더를 둘러보면서 키 몇 개로 파일을 주고받습니다.
- **기존 명령과의 관계:** `pull`은 그대로 둡니다. `files`는 터미널이 있어야만 동작하는 명령이라, 같은 일을 비대화형으로 하는 `pull` · `push`가 함께 있어야 원칙 6(사람이 없어도 동작)을 지킬 수 있습니다.
  - `ak pull`: 최근 파일을 골라 받기 (기존)
  - `ak push`: PC 파일을 디바이스에 올리기 (새로 추가, `files`보다 먼저 만듦)
  - `ak files`: 둘러보며 주고받고 정리하기
- **범위 밖:** 디바이스 루트 권한 작업, 앱 내부 저장소(`/data/data`), 원격 접속(망이 다른 경우). 셸 권한으로 접근할 수 있는 곳만 다룹니다.
- **업무 프로필 · 보조 사용자도 범위 밖입니다.** `/sdcard`는 주 사용자(0번) 저장소만 가리킵니다. 업무 프로필이 있는 Galaxy S24 Ultra(Android 16, 업무 프로필 = 사용자 10)에서 확인한 결과, 모든 경로가 막혔습니다.
  - `ls` · `adb pull` · `adb push`로 `/storage/emulated/10/...`에 접근 → `Permission denied` (`/data/media/10`, `/mnt/user/0/emulated/10` 등도 같음)
  - `content query` · `content read --user 10`, `pm list packages --user 10` → `SecurityException: Shell does not have permission to access user 10`
  - 원인: 업무 프로필에 기본으로 걸리는 `no_debugging_features` 제한(`dumpsys device_policy`의 `defaultEnabledRestrictionsAlreadySet`). adb 셸이 그 사용자에 접근하는 것 자체를 시스템이 거부하므로 우회할 수 없습니다.
  - 업무 프로필 파일은 기기 안에서 주 프로필로 공유한 뒤 다뤄야 합니다(회사 정책이 프로필 간 공유를 막을 수 있음).

## 2. 명령 정의

```
ak files [path]

  path  처음 열 디바이스 폴더 (기본: /sdcard)

  -s, --serial SERIAL   대상 디바이스 (공통)
```

- `Device: oneDevice`. 디바이스가 여러 대면 기존 선택 UI로 먼저 고릅니다.
- **터미널이 아니면** 바로 실패합니다.
  `Error: ak files needs a terminal` + `Hint: Use ak pull or ak push`
- `--json` 없음. 끝날 때 한 일을 stderr에 남깁니다(§8).
- 자동완성: `path`는 디바이스 경로라 제안하지 않습니다(`compArgs`에 "제안 없음").
- 에이전트용 SKILL.md에는 넣지 않습니다(대화형이라 에이전트가 쓸 수 없음). 대신 `pull` · `push`를 안내합니다.

## 3. 화면

### 한 창 (처음 화면)

```
 Galaxy S24 Ultra  /sdcard/DCIM/Camera                         name ↑
 ──────────────────────────────────────────────────────────────────────
   ..
 [✓] 20261119_101533.jpg                              3.2 MB   2m ago
 [✓] 20261119_101540.mp4                              430 MB   1m ago
 ➤   20261118_220011.jpg                              2.9 MB  12h ago
     20261118_215930.jpg                              3.1 MB  12h ago
 ──────────────────────────────────────────────────────────────────────
 Copy 2 files (433.2 MB) from Galaxy S24 Ultra:/sdcard/DCIM/Camera  v Paste  Esc Clear
 Tab PC  w Split  Space Select  c Copy  x Cut  d Delete  r Rename  n New folder  ? Help
```

- 맨 위: 위치(디바이스 이름 또는 `PC`, 경로), 오른쪽에 정렬 기준.
- 목록: 이름, 크기, 수정 시각(상대 시간). 폴더는 이름 뒤에 `/`, 크기 칸은 비웁니다. 폴더가 먼저 오고 그다음 파일입니다.
- **클립보드 줄:** 담은 것이 있을 때만 보입니다. 붙여넣는 동안에는 진행률로 바뀝니다(§6).
- **키 도움말 줄:** 지금 쓸 수 있는 키만 보여 줍니다.
- 처음 화면은 디바이스 쪽입니다.

### 두 창 (`w`로 켜고 끔)

```
 Galaxy S24 Ultra  /sdcard/DCIM/Camera   │ PC  ~/Downloads
 ────────────────────────────────────────┼────────────────────────────────
   ..                                    │   ..
 [✓] 20261119_101533.jpg  3.2 MB   2m    │ ➤ app-release.apk   12 MB  3d
 ➤   20261119_101540.mp4  430 MB   1m    │   notes.txt          2 KB  1h
```

- 왼쪽이 디바이스, 오른쪽이 PC입니다. 커서가 있는 창만 `➤`와 강조를 보입니다.
- **터미널 폭이 100칸 미만이면** 두 창을 켜지 않고 클립보드 줄 자리에 `Window too narrow for two panes`를 잠깐 보입니다. 두 창 상태에서 폭이 줄면 커서가 있던 쪽 한 창으로 돌아갑니다. 파일 이름이 잘려 못 읽는 것보다 낫기 때문입니다.
- 기존 선택 UI 규칙을 그대로 따릅니다: 대체 화면, stderr에 그리기, 터미널보다 높게 그리지 않기, `ui.Fit`, 크기 바뀌면 다시 그리기, 색이 꺼지면 기호만으로 구분([cli-design.md §10](cli-design.md)).

## 4. 키

기존 선택 UI는 글자를 치면 바로 필터가 되지만, `files`에서는 글자가 동작 키라서 필터는 `/`로 시작합니다.

| 키 | 동작 |
|---|---|
| ↑ ↓ · PgUp PgDn · Home End | 이동 |
| Enter · → | 열기 (§5) |
| Backspace · ← | 상위 폴더 |
| Space | 선택/해제 후 한 줄 아래로 |
| `*` | 이 폴더 전체 선택/해제 |
| `/` | 이름 필터 (Esc로 끄기) |
| Tab | 한 창: 디바이스 ↔ PC 전환 / 두 창: 커서를 반대쪽 창으로 |
| `w` | 두 창 켜기/끄기 |
| `c` | 복사로 클립보드에 담기 |
| `x` | 잘라내기로 담기 (붙여넣으면 이동) |
| `v` | 지금 폴더에 붙여넣기 |
| Esc | 필터가 있으면 필터 끄기, 없으면 클립보드 비우기 |
| `d` · Delete | 삭제 (확인) |
| `r` | 이름 바꾸기 |
| `n` | 새 폴더 |
| `t` | 디바이스 쪽: 최근 파일 보기 ↔ 폴더 보기 (§7) |
| `s` | 정렬 바꾸기: 이름 → 최신순 → 크기 |
| `.` | 숨김 파일 보이기/숨기기 (기본 숨김) |
| `g` | 경로를 입력해 이동 |
| `?` | 키 도움말 전체 |
| `q` · Ctrl+C | 끝내기 (붙여넣는 중이면 §6의 중단) |

- 각 쪽(디바이스 · PC)은 보던 폴더, 커서, 선택을 따로 기억합니다. 모드를 바꾸거나 Tab을 눌러도 그대로입니다.
- F키는 쓰지 않습니다. macOS 터미널에서는 F키가 밝기·볼륨 같은 시스템 기능에 먼저 걸리기 때문입니다.
- `c` · `x` · `d`의 대상: 선택한 항목이 있으면 그것, 없으면 커서 위 항목.

## 5. Enter (열기)

| 커서 위치 | 동작 |
|---|---|
| 폴더 · `..` | 들어가기 / 상위 폴더 |
| 디바이스의 파일 | PC 임시 폴더로 받아 기본 앱으로 열기 (`screenshot -o`와 같은 열기) |
| PC의 `.apk` | 지금 디바이스에 설치 (`install`의 자동 복구 그대로, 확인 질문은 화면 안에서) |
| PC의 그 밖의 파일 | 기본 앱으로 열기 |

- 디바이스 파일을 폰 화면에서 여는 방식(`am start` VIEW)은 쓰지 않습니다. Android 7부터 `file://` 공유가 막혀 앱마다 결과가 다르기 때문입니다.
- 임시 파일은 `os.TempDir()/ak-files/`에 두고, 다음 실행 때 지웁니다. 끝날 때 바로 지우면 아직 읽고 있는 앱이 실패할 수 있습니다.

## 6. 클립보드와 붙여넣기

- 클립보드는 **ak 안의 것**입니다(OS 클립보드가 아님). 담은 위치(디바이스 시리얼 또는 PC), 경로 목록, 복사/잘라내기, 전체 크기를 가집니다.
- 담은 뒤 어디로 이동해도 유지됩니다. 복사는 붙여넣어도 남아서 여러 곳에 붙일 수 있고, 잘라내기는 붙여넣기가 끝나면 비워집니다.
- 붙여넣기는 출발지와 도착지에 따라 바뀝니다.

| 출발 → 도착 | 복사 | 잘라내기 (이동) |
|---|---|---|
| 디바이스 → PC | `adb pull` | pull 성공 후 디바이스에서 `rm` |
| PC → 디바이스 | `adb push` | push 성공 후 PC에서 삭제 |
| 디바이스 → 같은 디바이스 | `cp -r` | `mv` |
| PC → PC | 파일 복사 | `os.Rename` (다른 볼륨이면 복사 후 삭제) |

- **이동은 복사가 성공하고 크기가 맞은 파일만 원본을 지웁니다.**
- 같은 폴더에 붙여넣으면(복사) 이름에 ` (N)`을 붙입니다. 같은 폴더로 잘라내기 붙여넣기는 아무것도 하지 않습니다.
- 폴더를 자기 안으로 붙여넣으면 거절합니다.

### 같은 이름이 있을 때

클립보드 줄 자리에 묻습니다.

```
 'IMG_0001.jpg' already exists.  o Overwrite  s Skip  r Rename (N)  · Shift = all
```

- 소문자는 이 파일만, 대문자(`O` `S` `R`)는 남은 파일 전부에 적용합니다.
- 기본값(Enter)은 Rename입니다. 데이터를 잃지 않는 쪽입니다.

### 진행 표시

```
 Pasting 2/3  20261119_101540.mp4  42% (180 / 430 MB)  Esc Cancel
```

- 바이트 진행률은 전체 크기를 알 때(디바이스 `stat` · PC `os.Stat`) 받는 쪽 파일 크기를 주기적으로 확인해 계산합니다. 모르면 스피너만 돕니다.
- 붙여넣는 동안에도 화면은 움직일 수 있지만, 동작 키(`c` `x` `v` `d` `r` `n`)는 막습니다.
- **Esc · Ctrl+C:** 지금 파일을 멈추고, 덜 받은 파일은 지우고, 남은 파일은 하지 않습니다. 잘라내기였다면 끝난 파일만 원본이 지워진 상태입니다.
- 끝나면 `✓ Pasted 3 files to ~/Downloads` 또는 `2 of 3 pasted, 1 failed`를 클립보드 줄에 보입니다. 실패가 있으면 Enter로 실패 목록(파일, adb 원본 메시지)을 엽니다.

### 미디어 스캔

- Android 11(API 30)부터는 `/sdcard` 쓰기가 FUSE를 거치므로 push · `mv` · `rm` 결과가 MediaStore에 바로 반영됩니다(Pixel 9 Pro Android 16, Galaxy S24 Ultra Android 15에서 확인). 따로 스캔하지 않습니다.
- Android 10 이하에서는 바뀐 파일마다 `am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file://<path>`를 보냅니다. **10 이하 실기기에서 확인 필요.**

## 7. 최근 파일 보기 (`t`)

- 디바이스 쪽 목록을 `pull`과 같은 MediaStore 최신순 목록으로 바꿉니다(최대 300개). 각 줄에 폴더 경로를 흐리게 붙입니다.
- 여기서도 `c` · `x` · `d` · Enter가 그대로 동작합니다. 붙여넣기 대상이 될 수 없으므로 `v`는 막습니다.
- 처음 열 때 `content query`가 약 1초 걸립니다(데이터 양과 무관한 고정 비용). 그동안 목록 자리에 스피너를 보입니다.

## 8. 삭제·이름 바꾸기·새 폴더

- **삭제는 항상 확인합니다.** 클립보드 줄 자리에 묻습니다.
  - 디바이스: `Delete 3 items from Galaxy S24 Ultra? This cannot be undone. [y/N]` → `rm -r`
  - PC: `Move 3 items to Trash? [Y/n]` → 휴지통으로 이동 (§10 결정 필요)
- 이름 바꾸기 · 새 폴더는 아래 줄에서 입력받습니다. 빈 이름, `/` 포함, 이미 있는 이름은 거절합니다.
- 디바이스 명령에 넘기는 경로는 모두 셸 따옴표 처리를 합니다(공백 · 한글 · `'` 포함 이름).

### 끝날 때 남기는 기록

대체 화면이 닫히면 셸 화면에는 아무것도 남지 않으므로, 한 일을 stderr에 요약합니다.

```
✓ Copied 3 files to ~/Downloads
✓ Moved 'a.txt' to Galaxy S24 Ultra:/sdcard/Documents
✓ Deleted 2 items on Galaxy S24 Ultra
```

실패가 있었으면 종료 코드 1, 없으면 0, Ctrl+C로 끝냈으면 130입니다([cli-design.md §4](cli-design.md)).

## 9. 구현 구조

- **목록 읽기:** 디바이스는 `stat -c '%F|%s|%Y|%n' <dir>/* <dir>/.*`(폴더 하나에 0.1초 안팎). `%n`이 마지막이라 앞의 세 `|`까지만 자르면 이름에 `|`가 있어도 안전합니다. 이름에 줄바꿈이 있는 파일은 건너뜁니다. 파싱은 순수 함수(`parseStat`)로 분리해 테스트합니다.
- **두 저장소를 같은 인터페이스로:** `List`, `Stat`, `Mkdir`, `Rename`, `Remove`, `Copy`를 가진 인터페이스에 `deviceFS`(adb) · `localFS`(os) 두 구현. 붙여넣기 표(§6)는 출발지 · 도착지 종류로 고릅니다.
- **화면:** 새 패키지 `internal/files`(가칭)에 상태(`state.go`, 순수 로직)와 그리기(`render.go`)를 나눕니다. 키 해석 · raw 모드 · 크기 변경 감지는 `internal/tui`의 것을 공개해서 같이 씁니다. 지금 `tui.Select`는 고르고 끝나는 picker라 그대로 늘리지 않습니다.
- **테스트:** 상태 전이(이동 · 선택 · 클립보드 · 충돌 처리)는 순수 함수 테스트, 붙여넣기 흐름은 `adbtest.Fake` + 임시 폴더로 테스트합니다.

## 10. 순서와 정할 것

### 만드는 순서

1. `pull` 조회 스피너 (작은 개선, 먼저)
2. `ak push` (비대화형 짝)
3. `ak files` 1단계: 한 창 · 두 창, 탐색, Enter 열기, 클립보드 복사 · 잘라내기 · 붙여넣기, 충돌 처리, 진행률, 삭제 · 이름 바꾸기 · 새 폴더, 최근 파일 보기
4. `ak files` 2단계: 정렬, 숨김 파일, 경로 이동(`g`), `.apk` 설치
5. `ak files` 3단계(필요하면): 디바이스 바꾸기, 디바이스 A → B 복사(PC 임시 폴더 경유), 앱 목록에서 APK 추출

### 정할 것

- **PC 삭제 방식:** macOS는 Finder(`osascript`)로 지우면 "되돌리기"가 되지만 처음 한 번 자동화 권한을 묻습니다. `~/.Trash`로 옮기면 권한은 필요 없지만 되돌리기가 안 됩니다. Linux는 freedesktop 휴지통 규격, Windows는 셸 API가 필요합니다. 휴지통을 못 쓰는 환경에서는 영구 삭제 + 강한 확인으로 할지 정해야 합니다.
- **`Android/data` · `Android/obb`:** 버전 · 제조사에 따라 셸 권한으로도 막힙니다. 막히면 목록 자리에 `Permission denied`를 보이는 것으로 충분한지.
- **`push`의 기본 위치:** `/sdcard/Download`로 할지.
